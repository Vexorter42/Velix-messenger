# Velix

**Мессенджер, который можно поднять у себя.**
Маленький сервер на Python, приложение для Windows, нативное для Android и веб-клиент — все говорят на одном протоколе поверх WebSocket.

## Что это

Velix — переписка для нескольких человек, которые знают друг друга: семьи,
компании друзей, небольшой команды. Сервер вы держите сами — на малине дома, на
VPS, на любой машине, которая не выключается, — и ваши сообщения не лежат ни у
кого больше.

Всё нарочно простое и скучное: история в одном файле SQLite, вложения обычными
файлами, никаких очередей, контейнеров и облачных аккаунтов. Запуск сервера —
это `python server.py`.

**Что умеет**

| | |
|---|---|
| 💬 **Переписки** | Группы, которые вы заводите сами и зовёте в них людей, плюс личные диалоги на двоих. Ответить, реакция, закрепить, переслать, копировать, удалить своё, поиск по тексту, «печатает…», кто в сети — всё в меню по правой кнопке или долгому нажатию. |
| ✓✓ **Галочки** | Одна серая — сервер принял. Две серые — дошло до всех участников. Две голубые — все прочитали. |
| 📷 **Вложения** | Фото, гифки (проигрываются прямо в пузыре), видео и любые файлы. Нажатие на фото открывает его во всё окно. Снимок экрана вставляется из буфера. Картинки сервер ужимает: фото с телефона на 7.5 МБ становится примерно 400 КБ. |
| 👤 **Аккаунты** | Регистрация по приглашению, пароли через scrypt, токены сессий, запирание после перебора. Код восстановления вместо писем на почту. Профиль с именем, рассказом о себе и фото. |
| 🔒 **Шифрование** | TLS 1.3 (`wss://`) с сертификатом Let's Encrypt. На открытый `ws://` клиент откатывается, только если у сервера нет сертификата, — и честно пишет об этом на экране. |
| 📱 **Телефоны** | Нативное приложение для Android (`Velix.apk`) — настоящие экраны, а не страница в рамке. Веб-клиент остался для айфонов и для уведомлений. |
| 🔄 **Обновления** | Кнопка в настройках. Сервер отдаёт свежую сборку, клиент подменяет себя и перезапускается — переустанавливать ничего не нужно. |
| 🌍 **Два языка** | Английский и русский, переключаются в настройках и применяются сразу. |

## Быстрый старт

```bash
pip install -r requirements.txt
python server.py
```

Сервер слушает порт 8765 по IPv4 и IPv6 — принимает подключения и с этой же
машины, и из локальной сети.

Дальше запускается клиент — оконный:

```bash
python gui.py
```

…или консольный, он говорит с сервером ровно так же:

```bash
python client.py
```

В поле адреса можно написать просто имя хоста (`velix.example.org`,
`192.168.0.225`) или имя с портом (`velix.example.org:9000`). Без порта
подставляется 8765. Клиент сначала пробует `wss://` и только потом `ws://`.

Для регистрации нужен код приглашения — он выдаётся на сервере:

```bash
python invite.py "для Маши"    # выдать код
python invite.py --list        # посмотреть, кто чем воспользовался
```

## Приложение для Windows

Готовый `Velix.exe` — один файл со встроенным Python, ставить рядом ничего не
нужно. Сборки лежат в разделе
[Releases](https://github.com/Vexorter42/Velix-messenger/releases):
`VelixSetup.exe` ставит программу в профиль пользователя, поэтому не просит
прав администратора, делает ярлыки в меню «Пуск» и на рабочем столе и удаляется
штатным способом.

Собрать самому (нужен `pip install pyinstaller`):

```bash
python -m PyInstaller --noconfirm --onefile --windowed --name Velix --icon icon.ico --add-data "icon.ico;." --collect-all customtkinter --collect-all darkdetect gui.py
```

Установщик собирается из `installer.iss` компилятором Inno Setup 6 — рядом
должен лежать собранный `Velix.exe`:

```bash
"%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe" installer.iss
```

Сами сборки в репозиторий не коммитятся: они весят три десятка мегабайт и
собираются из исходников. Версия задаётся в `version.py` и должна совпадать с
`AppVersion` в `installer.iss`.

## Телефоны

### Приложение для Android

`Velix.apk` в разделе
[Releases](https://github.com/Vexorter42/Velix-messenger/releases) — это
настоящий клиент: экраны собраны обычными видами Android, а с сервером он
говорит тем же протоколом, что и оконный. Подписано своим ключом, а не
магазинным, поэтому Android спросит разрешение поставить его вручную. При
первом запуске приложение спрашивает адрес сервера и запоминает его.

Умеет то же, что и оконный клиент: вход и регистрацию, список переписок и
участников, личные диалоги и группы, историю, фото из галереи и просмотр во
весь экран, галочки о доставке, реакции, ответы, закрепление, пересылку,
копирование, удаление — и оба языка.

Внутри нет ни одной сторонней библиотеки: даже WebSocket написан руками
(`android/java/org/vexorter/velix/Ws.java`), потому что в Android своего
клиента нет, а готовый притащил бы за собой Gradle. Для сборки нужен только
Android SDK:

```bash
python android/build.py
```

**Чего пока нет:** уведомлений при закрытом приложении. Для них нужен Firebase,
аккаунт Google и отдельный проект; веб-клиент ниже умеет это через браузер.

### Веб-клиент

Ставить ничего не нужно, и это же путь на айфон: сервер раздаёт его по тому же
адресу и порту, что и сам чат.

```
https://velix.example.org:8765/
```

Через меню браузера («Добавить на главный экран») страница ставится как обычное
приложение: со своей иконкой и без адресной строки. Токен входа запоминается,
пароль спрашивают один раз. Умеет то же самое плюс уведомления, когда
приложение закрыто.

Страницы лежат в каталоге `web` и раздаются прямо из `server.py`, так что второй
веб-сервер и второй проброс порта не нужны. Обычный GET получает файл, а запрос
с заголовком `Upgrade: websocket` уходит в чат.

## Если пароль забыт

Письма на почту тут не шлют: почту мы не спрашиваем, а сервер стоит у кого-то
дома. Вместо этого при создании аккаунта выдаётся **код восстановления** —
четыре группы по четыре знака, показывается один раз, на сервере остаётся
только его scrypt-хеш. Кнопка «Забыли пароль?» на экране входа спрашивает
логин, этот код и новый пароль.

Код одноразовый: после срабатывания выдаётся новый. Смена пароля заодно гасит
все сессии — тот, у кого был старый пароль, окажется выкинут.

Если и код потерян, новый выписывает тот, кто держит сервер, и передаёт лично —
так же, как передают код приглашения:

```bash
python recover.py gosha     # выдать новый код
python recover.py --list    # у кого код есть, а у кого нет
```

Подбирать код так же бесполезно, как и пароль: после пяти промахов логин
запирается на пять минут.

## Язык интерфейса

Интерфейс **по умолчанию английский**, русский включается в настройках (в окне)
или на экране профиля (на телефоне). Выбор запоминается и применяется сразу,
перезапуск не нужен.

Сообщения об ошибках сервер шлёт вместе с кодом, поэтому написанное сервером
человек видит на своём языке. Уведомление на телефон приходит на том языке, с
которым телефон подписался.

Переводы лежат в `i18n.py` (окно и консоль) и `web/i18n.js` (телефон). Ключом
перевода служит сама русская строка: в коде видно, что написано на экране, а
забытая строка сразу заметна.

## Свой сервер

### Шифрование

Сервер умеет `wss://` — тот же TLS, которым защищены банковские сайты.
Достаточно указать сертификат и ключ:

```bash
VELIX_CERT=/путь/fullchain.pem VELIX_KEY=/путь/privkey.pem python server.py
```

Без этих переменных он поднимается по открытому `ws://` и честно пишет об этом
в лог, а клиент показывает в шапке чата пометку «без шифрования».

Сертификат для домена на DuckDNS выпускается через проверку DNS — порт 80 для
этого не нужен:

```bash
sudo certbot certonly --manual --preferred-challenges dns \
  --manual-auth-hook /usr/local/lib/velix/duckdns-auth.sh \
  --manual-cleanup-hook /usr/local/lib/velix/duckdns-cleanup.sh \
  --deploy-hook /usr/local/lib/velix/velix-deploy.sh \
  -d '*.вашдомен.duckdns.org'
```

Просить сертификат сразу и на домен, и на маску нельзя: обеим проверкам нужна
одна и та же TXT-запись, а DuckDNS хранит только одну — вторая затрёт первую.
Маски достаточно, она покрывает все поддомены.

### Кто может подключиться

По умолчанию сервер принимает всех, кто дозвонился до порта. С переменной
`VELIX_ALLOWED_HOSTS` он пускает только тех, кто пришёл по перечисленным именам:

```bash
VELIX_ALLOWED_HOSTS=velix.example.org,localhost python server.py
```

Имя берётся из заголовка `Host` при рукопожатии, остальным сервер отвечает
`403`. Защитой это не является — заголовок подделывается за минуту, — но
случайный сканер, перебирающий адреса и порты, имени не знает и до чата не
доберётся.

### Резервные копии

`backup.sh` снимает копию базы через `sqlite3 .backup`, поэтому снимок
получается целостным, даже если в этот момент кто-то пишет сообщение. Вложения
копируются жёсткими ссылками и место занимают один раз. В `~/velix-backups`
хранятся последние 14 копий. Раз в сутки из cron:

```bash
30 4 * * * $HOME/velix/backup.sh >> $HOME/velix-backups/backup.log 2>&1
```

### Тестовый сервер рядом с боевым

Пути и порт задаются переменными окружения, поэтому на одной машине уживаются
боевой сервер и тестовый — со своими данными и без всякого касания живой
переписки:

```bash
VELIX_PORT=8766 VELIX_DB=~/velix-test/velix.db VELIX_MEDIA=~/velix-test/media python server.py
```

### Как выложить обновление

Сервер держит рядом с собой `updates/Velix.exe` и `updates/version.txt` и
сообщает клиенту, какая версия у него есть. Если она новее клиентской, в
настройках загорается кнопка «Обновить».

```bash
~/velix/publish-update.sh /путь/к/Velix.exe 1.8.0
sudo systemctl restart velix
```

Подмена обходит то, что запущенный exe перезаписать нельзя, зато можно
переименовать: старый файл отъезжает под именем `Velix.exe.old`, новый встаёт
на его место, программа перезапускается и при следующем старте подчищает
отложенный файл. Если что-то срывается на полпути, старый файл возвращается.

### Переменные окружения

| Переменная | Что задаёт |
|---|---|
| `VELIX_PORT` | Порт, который слушает сервер (по умолчанию 8765) |
| `VELIX_DB` | Путь к файлу базы |
| `VELIX_MEDIA` | Каталог для вложений |
| `VELIX_WEB` | Каталог с веб-клиентом |
| `VELIX_CERT`, `VELIX_KEY` | Сертификат и ключ TLS |
| `VELIX_ALLOWED_HOSTS` | Имена, по которым разрешено подключаться, через запятую |
| `VELIX_OPEN_REGISTRATION` | `1` снимает требование приглашения |
| `VELIX_UPDATES` | Каталог со сборкой, которую раздают клиентам |
| `VELIX_PUSH_KEYS` | Путь к файлу с ключами VAPID |
| `VELIX_LANG` | Язык интерфейса консольного клиента |

## Как устроено

| Файл | Что там живёт |
|---|---|
| `server.py` | Подключения, доставка, присутствие, раздача веб-клиента и обновлений |
| `storage.py` | SQLite: сообщения, люди, сессии, переписки, реакции, подписки |
| `protocol.py` | Общий язык: JSON-кадры, виды вложений, размерные лимиты |
| `accounts.py` | Пароли, проверки логинов, токены сессий |
| `media.py` | Сжатие картинок на сервере |
| `push.py` | Уведомления через службу самого браузера |
| `gui.py` | Оконный клиент в телеграмном оформлении |
| `client.py` | Консольный клиент |
| `web/` | Веб-клиент для телефона |
| `android/` | Нативное приложение для Android: WebSocket, протокол, экраны, сборка без Gradle |
| `i18n.py`, `web/i18n.js` | Переводы интерфейса |
| `store.py` | Что клиент помнит между запусками |
| `tray.py`, `autostart.py` | Значок в трее, запуск вместе с Windows |
| `updates.py`, `version.py` | Обновление на месте |
| `invite.py` | Коды приглашений |
| `recover.py` | Коды восстановления пароля |
| `backup.sh`, `publish-update.sh`, `test-server.sh` | Серверные хлопоты |

Сообщение уходит текстовым JSON-кадром, а байты вложения — отдельным двоичным
кадром следом. Оконный клиент держит сеть в отдельном потоке со своим циклом
asyncio и общается с интерфейсом через очередь: Tkinter нельзя трогать из
чужого потока.

Содержимое вложений само клиенту не летит: в истории приходит только описание,
а байты запрашиваются, когда доходит очередь показывать. Видео и вовсе
скачивается по нажатию кнопки — иначе открытие чата тянуло бы все ролики разом.

## Чего тут нет

- **Сквозного шифрования.** Сообщения защищены в пути, но на сервере лежат в
  открытом виде: у того, кто владеет машиной, есть вся переписка.
- **Главных в группе**: позвать нового может любой участник, а выгнать — никто.
- **Защиты от флуда** и ограничения длины сообщения.
- **Шифрования истории**: у любого, кто имеет доступ к `velix.db`, есть вся
  переписка.

Это переписка для тех, кто доверяет человеку, держащему сервер, — а не способ
скрыть что-то от него.
